# Storyboard Jam / CONTE LIVE

音楽に合わせてカットを切り替えながら、複数人で絵コンテを作るWebアプリです。

## 主な機能

- キャンバスへの描画、消しゴム、色・線幅変更、Undo / Redo
- タイムライン上でのカット区切りのドラッグ調整
- 1920×1080のフレームと、その外側の作業余白（書き出し対象外）
- 楽曲の長さがそのまま全体の尺になるタイムライン
- 再生位置でのカット分割、尺と演出メモの編集
- 音源のローカル読み込み、音量調整、タイムライン再生
- 再生位置に合わせたカットの自動切り替え
- タイムラインの拡大縮小（1〜8倍）
- キーボードショートカット
- WebRTCによるP2P共同編集（ホスト権威モデル）
- 連番PNG + After Effects用JSXスクリプトの書き出し
- 音声付きMP4（H.264 + AAC）の書き出し
- 書き出したZIP / フォルダの読み込み（作業再開）

音源ファイル・再生位置・音量・拡大率は参加者それぞれの端末に閉じています。絵、カットの区切り、メモ、全体の尺だけが同期されます。

## 尺とカットの考え方

**全体の尺は楽曲が決めます。** 音源を読み込むと、その長さがそのままタイムライン全体の長さになります。音源が未読み込みの間は仮に60秒として扱われます。

カットは「長さ」ではなく、楽曲上の**区切り位置**です。再生位置を合わせて `S` を押すと、そこで分割されます。最後のカットは常に楽曲の終わりまでなので、尺は編集できません。

区切りの調整方法は3通りあります。どれも全体の長さは変えず、隣り合うカットの間で時間を受け渡します。

- **タイムライン上の区切りをドラッグ** … 一番直感的です。離した時点で確定し、他の参加者へ配られます
- **区切りを選択して `←` / `→`** … 1フレーム単位、`Shift` 併用で1秒単位の微調整
- **カット情報の「尺」を数値入力** … 次の区切りが動きます

隣のカットは最小0.1秒まで詰められ、それ以上は動きません。

起動時はカットが1つあるだけで、名前も入っていません。曲を流しながら切っていく使い方を想定しています。

## キャンバスとフレーム

書き出されるのは中央の**フレーム（1920×1080）だけ**です。その外側には上下左右に200pxずつの作業余白があり、黒50%で暗く表示されます。

余白にも描けます。フレームからはみ出す勢いのある線を引いたり、画面外から入ってくる動きを描いたりするための領域で、**暗くなっている部分は書き出しに含まれません。**

線の座標はフレームを基準に正規化して保存しているため、ウィンドウの大きさを変えても、また他の参加者の画面サイズが違っても、書き出し結果は同じになります。

## ショートカット

画面右上の `?` ボタン、またはキーボードの `?` で一覧を表示できます。

| キー | 動作 |
| --- | --- |
| `Space` | 再生 / 停止 |
| `S` | 再生位置でカットを分割 |
| `B` / `E` | ペン / 消しゴム |
| `[` / `]` | ブラシを細く / 太く |
| `←` / `→` | 1秒移動（`Shift`併用で1フレーム） |
| `,` / `.` | 前 / 次のカットへ |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 元に戻す / やり直す |
| `Delete` | 選択中のカットを削除 |
| `?` | ショートカット一覧 |

## 同期のしくみ

ホスト（最初にルームを開いた人）のブラウザが絵コンテの原本を持ちます。

- ゲストの編集（描画・分割・区切りの移動・削除・メモ）はホストへ「操作」として送られ、ホストが適用してから全員へ配ります
- 保存されるのはホストの端末（localStorage）だけです
- **ホストがタブを閉じるとルームは終了し、全員が切断されます**
- サーバーはWebRTCのシグナリング（Durable Object）だけを担当し、絵コンテの中身は一切保持しません

作業内容を残したい場合は、終了前に書き出してください。

STUNのみを使うため、対称NATなど直接接続できない回線では接続に失敗することがあります。その場合はTURNサーバーの追加が必要です。

## 書き出し

画面右上の「連番＋AE」「MP4」から行います。

**連番＋AE** … 以下をまとめたZIPをダウンロードします。

```
images/cut_0001.png …   1カット1枚の1920×1080 PNG
<プロジェクト名>.jsx     After Effects用スクリプト
project.json            読み込み用のプロジェクトデータ（絵を含む）
cut_sheet.txt           カット表
timing.json             タイミングデータ
```

After Effectsで [ファイル > スクリプト > スクリプトファイルを実行] からJSXを選び、`images` フォルダ内の1枚目を指定すると、コンポ・タイムリマップのキーフレーム（HOLD補間）・カット名のマーカーまで自動生成されます。連番は「1枚＝1フレーム」として読み込まれ、Nカット目はソース時間 N/fps に対応します。音源は続けて表示されるダイアログで任意に指定できます。

## 読み込み

書き出したZIP、またはそれを解凍したフォルダを、そのまま読み込んで作業を再開できます。画面右上の **ZIP読込** / **フォルダ読込** から選んでください。

復元されるのは絵・カット割り・尺・メモ・プロジェクト名です。**音源は含まれないので読み込み直してください**（音源は元から各端末のローカル扱いです）。

復元の実体は `project.json` です。PNGからは絵を復元できないため、このファイルが無いZIPやフォルダを選ぶとその旨を表示します。`timing.json` しか無い古い書き出しの場合は、カット割りだけを復元します。

読み込むと、ルームの全員の内容が置き換わります。

**MP4** … 楽曲の長さ全体を音声付きMP4（H.264 + AAC）で書き出します。読み込み済みの音源がそのまま乗ります。WebCodecsを使うためChrome系ブラウザが必要です。AACに対応しない環境では音声がOpusになり、その場合After Effectsでは読み込めません（トーストで通知されます）。

## ルーム

URLの `?room=` がルームIDです。パラメータなしで開くとランダムなIDが発行され、URLに追記されます。「招待する」でURLをコピーして共有してください。IDを知っている人だけが参加できます。

## 必要なもの

- Node.js 22.13以上
- GitHubアカウント
- Cloudflare無料アカウント

## ローカル起動

```bash
npm install
```

```bash
npm run dev
```

表示された `http://localhost:3000` をブラウザで開きます。

## Cloudflareの初期設定

ログインするだけです。データベースの作成は不要になりました。

```bash
npx wrangler login
```

## 公開

```bash
npm run deploy
```

初回のデプロイでDurable Objectのマイグレーション（`SignalRoom`）が適用されます。成功すると `https://storyboard-jam.<アカウント名>.workers.dev` 形式のURLが表示されます。

## GitHubから自動公開

`.github/workflows/deploy.yml` により、`main` への push で自動デプロイされます。
GitHubリポジトリの Settings → Secrets and variables → Actions に以下を登録してください。

- `CLOUDFLARE_API_TOKEN` … Cloudflareダッシュボードで発行したWorkers用のAPIトークン
- `CLOUDFLARE_ACCOUNT_ID` … WorkersページのアカウントID

登録すると `wrangler login` は不要になります。

## 無料枠を守るための目安

同期はP2Pで行われるため、Workerへのアクセスは接続確立時のシグナリングだけです。無料枠の消費は非常に小さく、数人規模の共同制作であれば問題になりません。
